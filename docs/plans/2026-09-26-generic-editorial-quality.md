# 通用课件质量：覆盖诊断与来源总结

## 目标与边界

用户要求提升跨课程生成质量，停止按单个视频补充固定用法、固定例句数和固定总结文案。本次改造现有编辑与产物流程：先让丢失内容可追踪，再替换总结的课程专属规则。图片按原比例放置、原帧来源、证据 ID 和已有人工审阅记录继续保留。

现有 `KnowledgeDocument` 已有概念、例句、步骤、警告和回顾等 kind，以及 claim、topic 和关系，因此本次复用这些结构，不新增平行的知识 schema，不增加模型调用。模型语义正确性仍需证据核验与人工审阅；JSON 中存在 claim ID 不等于该知识点确实出现在可见文字中。

## 发现的专属规则

| 位置 | 当前行为 | 本次处理 |
|---|---|---|
| `edit_deck.py` 总结构建 | 只遍历三个固定用法，输出预设文字；为用法三检索特定日语和频率词 | 换为实际正文主题与来源条目的通用总结 |
| `edit_deck.py` 总结润色 | 总结压到三条，普通课程多主题也缺少可靠覆盖 | 移除三条假设，按单页容量分页或明确记录预算不足 |
| `prompts/editor.md` | 写死语法接续、日语例句、用法顺序、特定截图与页数上限 | 用主题、先修关系、例句、限制条件和证据覆盖描述编辑任务 |
| `edit_deck.py` 选页及 `grammar_sense.py` | 特定语法标题、原因两页/四例、关于一页、比例句抽取 | 仍是兼容路径；后续需用通用主题/例句关系与容量算法替换 |
| `student_copy.py`、`transcript_visual_correction.py` | 特定词头规范化、OCR 支持的 ASR 修正 | 仍保留；不能把词头改写扩大为无证据的任意文本替换 |
| `verify_claims.py` | 对特定语法接续页提供保留逻辑 | 仍保留；后续用带来源的先修内容规则替换 |

这份清单不是“全部已通用化”的声明。逐项迁移时应把具体视频的期待放进测试，不继续扩大生产代码中的句子匹配表。

## 内容覆盖报告

每次完成编辑与核验后生成 `editorial/content-coverage.json`，冷启动、缓存恢复和已有编辑计划均刷新。报告以最终供交付使用的计划为准，逐 claim 记录所属 unit/topic、来源类型、证据引用、正文页引用、总结页引用、明确的省略理由及缺口。

必须区别：正文引用、仅总结引用、明确省略、未交代。引用与省略冲突、未知 claim、无效证据引用、正文主题缺少总结，都应成为可定位的诊断。报告不猜测“重复合并”或“语义等价”，没有关系证据时只能报告已知事实。页面引用只代表结构覆盖，不代表模型文本蕴含源 claim，也不表示教学内容已经人工验收。

## 通用总结

总结取材于最终保留正文的主题和来源条目，不能从已删页面推导覆盖。每行携带对应 claim ID；生成实践题不能冒充源视频事实。较长条目不能按字符切掉后半句、否定或条件；保守回退可用来源主题标签，而不凭课程名称编造语义。

超过四个主题时不再固定裁为三个。分页遵守已有单页 schema 和调用方明确的 max_pages；预算无法容纳全部主题时保留可追踪的缺口，不能通过最后的列表切片把总结悄悄删掉。max_pages 是调用方约束，不是针对某个视频规定的总页数。

## 实施与验证

1. 通用总结与编辑提示实现概念课、流程课、语法课、多主题和紧预算回归；先复现失败再修改。
2. 覆盖报告及产物集成测试正文/总结/省略/缺口、错误引用、最终核验计划、缓存及人工编辑计划。
3. 主代理审阅两个改动的交集，检查总结分页、模型覆盖合同、产物刷新和缓存版本；运行完整离线测试与远端 CI。
4. 使用合成证据验证跨课程合同，不把测试文本或报告称为真实视频完整验收。真实例句遗漏的根因仍需本次运行的 transcript、knowledge、editorial-plan 与核验结果。

后续顺序：根据覆盖报告定位真实缺口；补通用例句与限制条件关系；用文字/图像容量替换特定语法页数上限；再加入固定证据重复运行的稳定性评测。每一步都须保留来源支持和跨课程退化检查。
