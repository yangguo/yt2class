# PR #15 ～につき讲义质量补强设计

**基线：** PR #15 的 `6009e584aa928ed19cb02996f31935822d04059f`。本设计补强现有的 M3 编辑和 M4 渲染流程，不改变原始媒体、证据合同或其他语法课的默认策略。

**目标：** 对有充分视频证据的 ～につき 课程，在有限页数内保留不同用法的代表例句，输出简短的学生讲义语言和准确的来源时间。原视频关键帧继续直接引用原始抽帧资产，不生成替代图像。

## 观察和证据边界

用户提供的首版 `lesson.pdf` 是 2026-09-24 的一次输出，共七个物理页。它是失败样本，不是对代码的指令，也不是上游知识文档。PDF 第 3、4 页各只有一条原因例句，日语原句和中文解释被拆成两个项目符号；第 7 页复制第 6 页的长解释；第 2、6 页可见“新知识导入（非复习）”“保留否定使わないで”等分析文字。第 4 页起的来源脚注重复显示 04:27。第 2 页原视频板书图像可见“店内改装中につき…”；用户给出的其他例句与时间点仍须对照视频、字幕或 OCR 的实际证据，不得仅因出现在目标清单里就写入生成结果。

目前工作区没有这次运行的 `KnowledgeDocument`、`EditorialPlan`、`SlideSpec` 或原始视频文件。故代码验收先使用可审阅的合成证据 fixture，真实 VGQ6 视频 / Ark 回归另列为独立门槛，不能用合成测试代替。

## 输出合同

### 1. 用法一的例句覆盖

- 保留 PR #15 的教学顺序：封面 → 接续 → 用法一 → 用法二 → 用法三 → 总结。用法一最多两页，但“两页”不等于“两条例句”。
- 从 `KnowledgeDocument` 中筛选属于原因／理由、具有 source provenance 和有效证据 ID 的不同例句。把日语原句及其已有中文释义作为一个教学单元；同义的中日 claim、同一句的不同 ASR 片段只计一次。先保留有板书／清晰语音支持的典型书面告示，再选不同情境的例句。没有证据的例句保留在 omission / review 记录，不补写。
- 在两页容量中优先展示至少四个**确有输入证据**的不同例句：两页各两条；如果输入少于四条，只展示可证实的内容并明确缺口。每页每条例句的 `claim_id` 必须与实际可见文字对应，绑定后必须还能追溯到 `citation_ids`。不要求为每句重复同一张板书。
- 总页数不固定为七。课程调用方应按视频长度、知识点密度和可读性设置 `target_pages`／`max_pages`；选择阶段按合并后的实际页面数计算容量，不能把四个例句候选误算成四张幻灯片。`target_pages=max_pages=7` 仅是复现附件规模的边界回归，用来证明紧凑课程也能正确合并；较长课程可使用更大的页面预算。
- 短例句可以“日语完整句（中文释义）”形成一个项目符号。较长例句可以在一个项目符号内换行；不能把半句和句末引号或解释拆成单独的项目符号。页面内容过长时要分页或减选，不能依靠 200 字符切片截断日语原句。

### 2. 总结页

- 总结回答“这三种用法有什么区别”，只显示三条短句：原因・理由（书面公告等）、比例・单位（每个单位）、关于（罕用，通常使用「について」）。语义均来自已选且有证据的用法，不把长篇源 claim 直接复制到总结。
- 对每条设置明确的长度上限和去重检查。用法三必须保留“通常用「について」”这一否定／偏好语义，但学生可见文字不得出现“保留否定”“老师指出”“对比点”等分析过程词。总结可引用来源 claim ID，显示文字与 claim 原文分开处理。
- `PageIntent.body_points`、`SlidePage.bullets` 和实际 PPTX 中的可见文字应一致。缺少某一用法时不能伪造完整三行总结；按现有质量标签显示可证实内容，并保留缺口记录。

### 3. 学生文案

- 独立语法词头 `につき` 可显示为 `～につき`；完整例句 `本日雨天につき…`、`店内改装中につき…` 的句中字符必须原样保留。
- 编辑阶段把内部分析信息与学生可见字段分开：`selection_reason` 和诊断记录继续留内部；学生可见的标题、项目符号、图片说明、讲者注释只保留教学信息。清理不应通过宽泛关键词删除真实语法说明中的否定、条件、数字或单位。
- 对 PDF 已暴露的语句做自然表达：接续页用“名词／数量词＋につき”；用法三用“表示‘关于’时，多数场合使用「について」”。这类改写必须依据输入 claim 的含义，不能给无关课程强行套用。

### 4. 来源时间和可视化

- 重新按教学顺序排列页面后，各内容页的来源时间须由本页证据决定。不可用上一页的时间向前覆盖，从而把较早的用法二／三错误地标成 04:27。
- 如果一页有多条例句，页脚只代表该页的主证据；保留各 claim 的证据 ID 供审阅和后续逐条跳转。总结页覆盖多处证据时，不显示单一虚假的来源时间。没有有效时间则不生成可点击来源链接。
- 保持现有帧原图及版权／哈希引用；视觉验收检查字幕不遮挡、项目符号不裂句、底部来源链接不混淆。

## 实现边界

主要修改 `src/yt2class/stages/edit_deck.py`、`student_copy.py`、`grammar_sense.py`、`bind_spec.py`，以及 `renderer/src/render.mjs` 与布局辅助。若引入“例句教学单元”辅助结构，保持其内部实现简单，不扩大 SlideSpec 公共 schema，除非真实逐句来源链接必须依赖新字段；任何 schema 变化都需同步合同测试和已有打包流程。

PR #15 的强制用法覆盖、接续页、用法二三种比例示例、质量状态和原视频帧选择必须保持。不能把用户给出的 VGQ6 例句写成按视频 ID 匹配的生产规则。

## 验收

1. 新增最小失败 fixture：四个有证据的原因例句分布在多个 topic／时间窗，另有重复翻译、比例句和无证据句；当前 PR 会漏句。用七页作为紧凑边界测试时，修复后两张用法一页应覆盖四句且不混入比例句；该测试不规定其他视频的总页数。
2. 文案测试先复现句中误加 `～`、分析词泄漏和长总结；修复后原句字面完整，总结三条短句，重复度和长度达到本设计要求。
3. 渲染测试先复现教学顺序下时间回填；修复后每个内容页使用本页证据时间，总结不冒充单个时点。
4. 运行相关 unit／contract／integration 和完整 `uv run pytest -q`，构建 PPTX，逐页查看 PPTX 导出 PDF。通过 CI 只能证明离线合同，不等于真实 VGQ6／Ark 验收。
5. 若可获得授权的视频、运行目录与 Ark 额度，再独立记录一次端到端生成的输入版本、输出页码、核心例句覆盖、逐页视觉、来源跳转和人工审阅结论；没有这些条件时明确标为未验证。

## 2026-09-25 再生成结果补充

用户新提供的六页版 `lesson.pdf` 的物理页 2、4、5 含原视频截图。PDF 内嵌的 JPEG 均为 1259×708（约 16:9），但显示宽高约 4.2×3.8 英寸；`pdfimages -list` 的水平／垂直有效 PPI 为 300／186，说明是放置形状拉伸而非原图比例错误。M4 应按图像原始宽高计算实际放置矩形，在封面、图文、对比、步骤布局通用；PPTX 包内图片形状宽高比和导出 PDF 视觉都要验证。不得修改原始帧字节、哈希或来源时间。

修复后的独立验证从附件提取第一张原 JPEG，重新用图文布局输出 PPTX／PDF；新 PDF 的水平／垂直有效 PPI 为 300／300，PPTX 中的图片字节哈希与提取的原 JPEG 一致。这验证比例和原图保留，不等于已重新运行完整 VGQ6 分析流程。

这份 PDF 的用法一页只有“店内改装中”和“本日雨天”两条例句，另外两条只凭 PDF 无法判断是上游知识提取遗漏，还是编辑选择舍弃；运行目录尚未找到。编辑阶段存在逐 topic 只保留两条例句的限制，因此要新增“四个不同、有证据的原因例句同属一个 topic”的回归：在可用页面预算下保留四句、分至可读页面，并保留用法二／三。若输入证据没有“工事中”或“限定品”，只记录缺口，不由用户给出的目标文本补写。总页数由课程内容与配置决定，六页／七页均非通用目标。
